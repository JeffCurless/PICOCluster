I want to setup a number of Raspberry PI PICO W's so that each PICO has PCode based kernel that can have multiple threads of execution and a well defined instruction set.  There are several requirements:

1) A PCode system will be created.  The PICO will execute an interpreter that runs the PCODE, and executes
   each instruction.  Periodically the pcode will switch threads to execute other instructions. There will 
   be instructions that will causee at thread switch.  Any instruction that requres a resource will automatically
   switch treads.
2) The network on all of the PICO's will be used for communiations between the PICO's.  The SSID and PASSWORD will
   stored in a configuration file on the PICO.
   a) All of the PICOs would periodically announce their availability, current load, and memory available.
   b) A non-PICO (Possibly a raspberry PI would be used as a "file storage" area, and PICO specific files would
      live on each specific PICO.
   c) Threads would need to be protected against each other via a locking mechanism
   d) A shared memory concept needs to be created, where we utilize a "file" to store any data that needs to be
      shared between systems.
   e) When the term "file" is used, there is zero expectation that a protocol such as NFS or SMB would be used.  I would
      think that all file based operations would simply be reads and sends over tcpip (or UDP)
3) A key component to this environment is that threads can execute on any node in the system.  For instance, the system
   would be able to recognise that a specific node as under utiized, and launch a thread on that node... handing off the
   code and data to the remove PICO.
4) Instructions.  Basic instructions include math (Addition,subtraction,multiplication,division,modulus,sqrt), along with
   call, return, jump, conditional jumps.  StartThread, EndThread, print, message. As well as others.
